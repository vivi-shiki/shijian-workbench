# 古籍截图转现代阅读版制作规范

- 文档版本：`0.1.0-draft`
- 制定日期：`2026-09-05`
- 适用范围：诗集、词集、曲集、诗文合集，以及带笺注、评点的中国古籍
- 当前验证样本：《疑雨集注》

## 1. 目的

本规范用于把古籍截图、扫描页和多套 OCR 结果制作成可校订、可追溯、可评测的现代阅读版数据。它同时约束人工标注、外部模型候选、Agent 操作、程序校验和最终批准。

最终成果必须同时满足：

1. 忠实：没有证据的字词不得补写、改写或现代化。
2. 可追溯：每段文字和每个结构判断都能回到原页及 OCR 片段。
3. 分层：原始证据、忠实转录、语义结构、现代句读和显示排版不得相互覆盖。
4. 可审核：AI 只能生成候选，正式结论必须经过明确批准。
5. 可评测：标准答案、错误案例和运行记录能够重复判断新版本是否改进。

本规范不负责规定具体字体文件、CSS 主题、PDF 引擎或 OCR 服务商。它规定的是这些系统必须消费和保留的数据语义。

## 2. 规范用语

- **必须**：不得省略的要求；违反即为不合格。
- **应当**：默认遵守；偏离时必须记录理由。
- **可以**：可选能力，不影响最低合格条件。
- **证据**：原页图像、OCR 原始输出、人工明确校订、可信外部版本及其来源。
- **候选**：尚未得到人工批准的 AI 或程序输出。
- **标准答案**：按本规范审核并标记为 `approved` 的结果。
- **现代阅读版**：在不改变原文字词的前提下增加句读、段落和现代显示结构的版本。

## 3. 数据分层

制作过程必须保留以下层次：

```text
Source       原始页图、处理图、坐标变换
Observation  各 OCR 的原始文字、框、置信度和版面标签
Transcript   人工确认的忠实文字与阅读顺序
Structure    书、卷、章节、作品、正文、注文及其关系
Edition      现代标点、分段、注码和显示顺序
Render       HTML、Markdown、TXT、EPUB、PDF 等导出物
```

后层可以引用前层，但不得覆盖或冒充前层。导出物必须能够声明自己基于哪些已批准版本生成。

当前项目尚未把所有层拆成独立文件。过渡期按以下方式理解：

- `pages/`、`ocr/` 和 `results/*.json` 承载 Source、Observation 及部分 Transcript。
- `edited_text` 只有在 `review_status` 明确表示人工确认时，才属于已批准 Transcript；文件名含 `edited` 不代表已校对。
- `ebook/structured.json` 当前同时承载 Structure 和 Edition。
- `history/` 记录事实流水，`ai-memory/` 是派生视图，不是标准答案。

## 4. 证据优先级

发生冲突时按以下顺序判断：

1. 当前原页图像中清晰可见的文字和版面关系。
2. 用户对指定位置作出的明确校订。
3. 经人工批准的本项目转录和结构。
4. 同一页的多套 OCR 互证。
5. 有版本信息、可定位页码的可信外部版本。
6. 本项目已批准的惯例和相似案例。
7. 模型语言知识、格律推断和常见搭配。

第 7 类只能用于提出候选或风险提示，不能单独支持改字、补字、删字和作品边界结论。格律异常可以触发复核，但不能据此修正文献。

## 5. 标识、坐标和文本位置

### 5.1 稳定标识

Page、Region、Fragment、Work、Note、Issue、Case 和 Run 都必须有稳定且唯一的 ID。重新排序不得改变对象 ID；拆分、合并时必须记录旧 ID 与新 ID 的关系。

### 5.2 图像和坐标

每张图像必须记录：

- 文件哈希、像素宽高和来源页。
- 旋转、裁切、缩放、透视校正和去弯曲参数。
- OCR 坐标实际对应的是原图还是处理图。
- 从处理图映射回原图所需的变换信息。

框坐标必须声明格式，例如 `xywh`、`xyxy` 或 polygon。禁止把去弯曲图上的框直接叠加到原图上而不记录变换。

### 5.3 文本位置

文本范围统一使用 Unicode 码点计数和半开区间 `[start, end)`。不得使用 JavaScript UTF-16 code unit 作为跨系统存储标准。

来源引用建议包含：

```json
{
  "result_id": "pp-ocrv6",
  "page_id": "page-0034",
  "region_id": "region-0017",
  "text_layer": "edited_text",
  "revision": 2,
  "start": 0,
  "end": 7
}
```

一个语义对象可以引用多个不连续、跨框或跨页片段。数组顺序表示文字拼接顺序，不同 OCR 的同一文字候选不得当作连续文字拼接。

## 6. 原始证据制作

每页必须保存原图。任何用于 OCR 或标注的处理图也必须单独保存，不得覆盖原图。

每次 OCR 运行至少记录：

- provider、model、model version 和结果 ID。
- 运行参数、预处理参数和时间。
- 输入图像哈希。
- 原始接口响应，不只保存清洗后的文本。
- 文字框或 polygon、原始顺序、标签和置信度。
- 接口失败、空响应和重试信息。

多套 OCR 结果必须保持独立。融合时创建对应关系，不得把其中一套覆盖为另一套的文本。

大块 OCR 与细框 OCR 的对应必须允许一对多、多对一、多对多和未匹配。对应关系置信不足时标为候选，不得强制合并。

## 7. 忠实转录规范

忠实转录只回答“原书写了什么”和“按什么顺序读”，不增加现代标点，不润色，不翻译。

### 7.1 字符

- 保留原书繁体字、异体字、俗字和可辨识的通假写法。
- 不因现代字形习惯自动改为简体或通行字。
- OCR 明显误字必须有原图、人工校订或可信版本证据才能修正。
- 无法辨认但原书明确占一个字位时使用一个 `□`。
- 连续缺失几个字位就保留几个 `□`；字位数量也不确定时，另建 Issue，不伪造数量。
- 原书已有标点、圈点和校记符号应作为原书符号保存，不与现代标点混淆。

### 7.2 增删与规范化

- 不得按上下文补写原书没有的字。
- 不得按格律补齐诗句。
- 不得静默删除重文、衍文或疑似错刻。
- 需要提供现代规范字时，应建立独立 normalization 层，并保留忠实字形。
- 外部现代整理本只可作参考；采用其文字时必须记录版本、页码和采用理由。

### 7.3 阅读顺序

- 竖排通常从右向左、栏内从上向下，但不能只依赖坐标机械排序。
- 必须先区分正文大字列、双行小字、题名、边栏和版心，再决定局部顺序。
- 双行小注通常作为一个注文单元阅读，但必须由版面位置和句意共同确认。
- 一页存在正文与注文交错时，分别保存正文顺序和注文内部顺序，不把两者展平成错误的单一字符串。
- 阅读顺序不确定时保存多个候选并建立 Issue。

### 7.4 区域角色

忠实层至少应能表达以下角色：

```text
heading, title, author, main_text, annotation,
preface, biography, colophon, page_number,
running_header, publisher_info, watermark, other, unknown
```

区域角色只是版面观察，不等于最终作品结构。一个 OCR 大框可以包含多个角色；一条注文也可以跨多个 OCR 框。

## 8. 语义结构规范

### 8.1 目录层级

- 卷名、章节、年份和类别标题使用 heading。
- `heading_level=1..6` 表示抽象层级，1 最高。
- 年份标题不得写入某首诗的 title 或 subtitle。
- 扉页题字、卷端撰注者、出版题记等使用 book_text。
- 作者传使用 biography，序跋使用 preface 或 colophon。

### 8.2 作品边界

- 每个独立作品建立一个条目。
- 题名必须结合字号、栏位、题名后的注文及下一题名位置判断。
- 没有独立题名时 `title` 留空，不得用正文首句补作题名。
- 作品跨页时仍为同一个最终条目，来源可以包含多页。
- `continuation_of` 只作为候选生成和合并操作；应用后的正式结构应形成一个连续作品。
- 换页、换栏和 OCR 分块本身都不能证明作品结束。

### 8.3 诗、词、曲和其他韵文

- 当前 schema 使用 `kind=poem` 承载独立韵文，具体体裁写入 `form`。
- 每个 `lines` 元素只放一个语义诗句，不得把两句、四句或整首诗粘成一项。
- 绝句、律诗的句数和字数用于检查，不用于猜补。
- 古体、乐府、联句不得强套近体诗句数。
- 词、曲按词牌或曲牌句式断句；当前格式使用空字符串表示上下阕时，必须由校验器允许并确认字符守恒。
- 体裁不确定时使用空值或 `unknown`，并建立 Issue。

### 8.4 组诗

- 组诗必须一首一个作品条目。
- 各首使用相同 `series.title`，并记录递增的 `series.index`。
- `series.total` 只有在总数有充分证据时填写。
- 组题只能写在 `series.title`；没有子题时，各首 `title` 留空。
- 不得把总题或首句复制为各首标题。
- 组题注文锚定 `field=series`，不得误挂到第一首正文。

### 8.5 作者、题下注和篇后附注

- 全书作者、作品作者、注文引用作者和文末落款必须区分。
- 只有版面和语义明确支持时，才把署名写入作品 `author`。
- 题名之后的作者说明、创作缘起和小字说明与作品标题分开保存。
- 正文结束后的作者自注、编者说明和跋语必须区分类型；身份不明时不强行判断。

### 8.6 注文

每条注文至少必须保存：

- 稳定 Note ID。
- 忠实文本及其来源片段。
- 所属作品。
- 正文锚点或题名、组题锚点。
- 注文在原页的版面顺序。
- 审核状态和不确定项。

当前 schema 的位置格式为：

```json
{
  "field": "lines",
  "line": 2,
  "offset": 5
}
```

- `line` 从 1 开始。
- `offset` 表示该行第几个 Unicode 字符之后。
- 题名注文使用 `field=title`，组题注文使用 `field=series`。
- 必须先确定注文实际所注词语，再设置 offset。
- 不得为省事统一挂在句末。
- 不得合并锚点不同的两条注文。
- 只能确认到整句时，应记录锚点粒度为 sentence 或建立 Issue，不得伪造精确词位。

### 8.7 散文

- 序跋、传记、题记等文字进入 `prose`。
- 忠实层保留连续原文；Edition 层按文意增加标点和自然段。
- 不得按固定字数机械分段。
- 文末落款不能自动提升为篇名作者。

### 8.8 未决问题

任何证据不足的文字、边界、类型、作者、注文归属或跨页关系都必须进入 Issue，不得用低置信猜测填平。

Issue 至少包含：

```json
{
  "id": "issue-0042",
  "category": "uncertain_character",
  "severity": "major",
  "source_refs": [],
  "description": "原页此字漫漶，两套 OCR 分别识为甲、乙。",
  "candidates": ["甲", "乙"],
  "status": "open"
}
```

## 9. 现代句读规范

现代句读属于 Edition 层，不属于忠实转录。

- 只能增加、删除或调整标点和空白，不能修改原文字词。
- 去除现代标点和空白后，字符序列必须与对应忠实文本完全一致。
- 诗句按句意和体裁添加标点；格律只作辅助。
- 长题可增加逗号、句号、冒号、引号和书名号，但不能拆掉或补写原题文字。
- 注文按完整句意断句，不能只在末尾机械添加句号。
- 序跋和传记按论旨转换、叙事阶段和落款划分自然段。
- 原书符号与现代标点必须可以区分来源。

字符守恒不等于句读正确。程序检查通过后仍需语义审核。

## 10. 现代排版规范

语义 JSON 保存内容与关系，字体、字号、颜色、页边距和分页由渲染模板决定。

最低显示规则：

- 标题、作者、题下注、正文和篇后附注分别显示。
- 近体诗在数据中一项一句；阅读界面可以每两句显示为一行。
- 词、曲按已批准的分阕和句式显示，不套用律诗布局。
- 注码按正文首次引用顺序生成，内部稳定 Note ID 与显示编号分开。
- 正文注码可以跳转到注文，注文可以返回正文。
- 原书页码和来源页能够查看，但不重复混入阅读正文。
- `□`、异体字和生僻字不得因字体缺失而静默消失。
- 草稿导出必须明确标记含未审核内容。

## 11. 状态与批准

制作资产使用以下状态：

```text
draft       尚在录入
proposed    已形成候选，未获人工确认
approved    已对照证据并明确批准
rejected    已确认不采用
superseded  被更新版本取代
```

只有人类可以把内容标记为 `approved`。外部模型、Codex、程序校验和独立评审模型都只能提出候选或检查意见。

批准记录至少包含：

- 批准对象 ID 和内容哈希。
- 批准者、时间和说明。
- 所依据的图像、OCR 和规范版本。
- 批准范围：局部事实、本项目惯例或通用规则。
- 是否包含仍未解决的 Issue。

批准一个候选不等于批准其中隐含的通用规则。规则必须单独确认适用范围。

## 12. 标准样本制作流程

每组标准样本按以下步骤制作：

1. 选取连续页面并说明选择原因和覆盖的难点。
2. 冻结原图、处理图、全部 OCR 原始结果和文件哈希。
3. 建立稳定 Page、Region 和 Fragment ID。
4. 对齐多套 OCR，保留冲突和未匹配项。
5. 第一遍制作忠实转录、区域角色和局部阅读顺序。
6. 第二遍重新对照原图复核字符，尽量在不同审核会话中进行。
7. 标记所有疑字，不因完成度要求强行确定。
8. 基于已复核转录制作作品边界、组诗、跨页和注文关系。
9. 独立检查来源覆盖：所有正文有来源，所有有效来源有去向或明确忽略理由。
10. 制作现代句读候选并运行字符守恒检查。
11. 检查现代排版样张、注释链接、生僻字和页面溢出。
12. 记录人工修订意见并再次校验。
13. 用户明确批准后，将相关资产标为 `approved`。
14. 从批准结果提炼错误案例；不得把整个标准答案直接当提示词规则。

## 13. 错误案例规范

一条案例应聚焦一个主要失败模式，至少包含：

```json
{
  "id": "yongshi-four-quatrains",
  "task_type": "series_structure",
  "error_tags": ["merged_works", "missing_work"],
  "genre_tags": ["poem", "qijue"],
  "layout_tags": ["vertical", "cross_page"],
  "scope": "general",
  "severity": "critical",
  "evidence_refs": ["page-0034", "page-0035"],
  "wrong_output_ref": "run-old/output.json",
  "approved_output_ref": "structure.gold.json#yongshi",
  "root_cause": "按批次和总句数判断边界，未识别共同组题。",
  "assertions": [
    "组诗共有四首",
    "各首为四个七言句",
    "序号为一至四"
  ],
  "forbidden_changes": [
    "不得补写原页没有的文字",
    "不得修改相邻作品"
  ],
  "status": "approved"
}
```

错误类别建议优先使用稳定标签：

```text
ocr_substitution, missing_character, extra_character, uncertain_character,
reading_order, region_role, title_boundary, work_boundary,
merged_works, split_work, missing_work, duplicate_output,
cross_page_link, series_relation, author_attribution,
note_owner, note_anchor, note_merge, punctuation,
paragraph_boundary, out_of_scope_change, missing_source
```

`scope` 只能是：

- `local`：只对指定页或作品成立。
- `project`：本书或本版本的惯例。
- `general`：可推广到同类古籍。
- `validation`：主要应由程序机械检查。
- `ambiguous`：证据不足，暂不形成规则。

## 14. 数据集与信息隔离

批准案例必须按用途隔离：

1. **示例库**：可向生成模型提供的少量相似案例。
2. **回归集**：输入可以运行，预期结果和断言只供评估器使用。
3. **隐藏评测集**：页面选择、标准答案和断言均不得进入提示词或 AI 概览。

同一案例不得同时作为生成示例和泛化能力证明。Agent 检索示例时，应按任务类型、错误标签、体裁和版式选择 1 至 3 条，不得把全部历史发送给模型。

原始反馈可以进入历史记录，但模型任务必须使用分析后的任务规格。评测断言、人工标准答案和当前评测页的正确结论不得泄漏给生成模型。

## 15. 运行记录

每次模型或 Agent 执行至少保留：

- Run ID、任务规格和可修改范围。
- 只读上下文和实际输入证据。
- 基线内容及哈希。
- prompt、Skill、代码、案例库和项目经验版本。
- provider、model、采样参数和重试轮次。
- 实际请求、原始响应和解析后的候选。
- 候选哈希、结构差异和字符差异。
- 自动校验、回归检查和人工审核结果。
- token、成本、耗时、失败原因和批准记录。

密钥不得写入日志。重试不得覆盖上一轮记录。修改任务范围、输入证据或基线后必须创建新任务或明确的新版本。

## 16. 评测规范

### 16.1 硬性门槛

以下任意一项失败，候选不得应用：

- JSON 或 schema 无效。
- 修改任务范围外内容。
- 基线已变化。
- 输出正文缺少有效来源。
- 发生无法解释的漏字、增字或重复内容。
- 句读任务改变原文字词。
- 注文位置越界或目标不存在。
- 批准哈希与候选不一致。

### 16.2 分层指标

- 忠实转录：CER、漏字率、衍字率、疑字召回率。
- 版面理解：区域角色准确率、阅读顺序成对准确率。
- 作品结构：边界 Precision/Recall/F1、类型准确率、组诗关系准确率。
- 跨页：续接准确率、错误合并率、重复输出率。
- 注文：正文/注文分类、所属作品准确率、锚点准确率。
- 句读：标点边界 F1、段落边界 F1、原字保存率。
- 可追溯性：有完整来源引用的输出比例。
- 人工效率：每页审核分钟数、每千字修改数、无修改批准率。
- 运行效率：每页成本、延迟、重试率和无效响应率。

早期不得只用一个综合分数掩盖严重错误。必须同时报告硬性门槛、各层指标、关键错误数和人工审核成本。

### 16.3 严重程度

- `critical`：漏字、增字、错误作品边界、注文归错作品、错误跨页连接、来源伪造。
- `major`：标题、体裁、组诗、作者、注释锚点或影响理解的句读错误。
- `minor`：不影响文字和语义的显示、空白或样式问题。

一次执行只有在硬性门槛通过、Critical 为零、相关回归无退化并完成所需人工审核后，才可以批准。

## 17. AI 概览生成规范

`AI_CONTEXT.md` 等概览必须由事件流和批准案例自动生成，不得手工编辑，也不得把所有历史修改简单拼接进去。

概览只应包含：

- 不超过 10 条已批准的本项目惯例。
- 当前任务相关的高风险错误类别。
- 3 至 5 条短案例：问题、判断证据和正确行为。
- 未解决 Issue 的索引，不包含猜测答案。
- 最近固定评测集的版本对比。
- 每条规则的适用范围和批准状态。

以下内容不得作为生成模型的事实上下文：

- 只有 AI 产生、未获人工批准的改动。
- 单纯的字段修改次数和标点频率。
- 隐藏评测集的预期结果。
- 与当前任务无关的大量案例。
- 无法回到原页证据的历史结论。

## 18. 版本管理

以下变化必须提升规范版本：

- 忠实转录字符政策变化。
- 作品、组诗、注文或跨页关系定义变化。
- source span 或字符 offset 计算方式变化。
- 批准状态和评测口径变化。

修正文句、补充示例和不改变语义的说明可提升补丁版本。语义字段兼容扩展提升次版本；破坏已有解释的变化提升主版本。

每份标准答案和评测报告都必须记录所使用的规范版本。规范升级后应声明哪些旧资产需要迁移或重新审核。

## 19. 样本完成清单

一个页面组只有全部满足以下条件，才算完成：

- 原图、处理图和 OCR 原始响应已冻结并有哈希。
- 坐标对应图和变换已声明。
- 多 OCR 冲突没有被静默覆盖。
- 忠实文字已经过至少两遍对图检查。
- 所有有效文字都有语义去向或忽略理由。
- 所有语义文字都有来源引用。
- 作品、组诗、跨页和注文关系已审核。
- 所有疑字和歧义都有 Issue。
- 句读字符守恒检查通过。
- 排版样张、注释链接和生僻字显示已检查。
- 错误案例包含错误输出、批准结果和断言。
- 批准记录包含内容哈希和规范版本。
- 样本用途已标明为示例、回归或隐藏评测，且不存在信息泄漏。
